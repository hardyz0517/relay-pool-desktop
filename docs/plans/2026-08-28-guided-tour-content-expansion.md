关联入口：[`../README.md`](../README.md)、[`2026-08-27-guided-tour-system.md`](2026-08-27-guided-tour-system.md)、[`../audits/2026-08-27-guided-tour-webview-acceptance.md`](../audits/2026-08-27-guided-tour-webview-acceptance.md)

适用范围：现有 Driver.js / `TourManager` 基础设施之上的教程信息架构、首次引导、页面教程、精选完整体验、教程中心分组、普通模式页面锚点、可逆视图准备、进度版本与前端测试。

> 本计划是待实施的一次性工程计划，不替代当前代码和自动化契约。实施时必须保留工作区内其他改动，并在每个阶段完成对应验证后再推进。

## 实施结果

本计划已于 2026-08-28 完成。当前发布目录包含 `full`、`basic` 和九篇普通页面教程；`proxy`、`station-setup` 等旧 ID 只保留进度解析兼容，不再发布。`full` 是独立维护的 17 步精选流程，完成后只记录自身，不推导任何页面教程状态；设置阶段会提醒用户优先使用系统代理访问可能无法直连的中转站。

实际实现遵循稳定 DOM 而非机械照搬草案锚点：中转站、密钥池和价格页只锚定稳定的汇总、工具栏和列表外壳；使用记录在普通模式没有筛选器和详情面板，因此使用显示控制与列表外壳，并复用列表解释结果、耗时、Token 和成本。所有开发者模式页面、开发者详情和任务式业务操作仍被排除。

路由与渠道状态通过窄的可逆视图端口完成 Tab 准备；页面不读取教程目录、进度或 `TourManager`。真实 WebView 验收还发现并修复了两个基础设施问题：普通末步此前会直接完成而不显示结束卡片，以及结束卡片曾被业务 Dialog guard 误判并关闭。现在所有教程都先进入显式结束确认，只有点击“完成”后才写入完成状态。

验证结果：

- 教程及相关页面聚焦测试：17 个文件、115 个测试通过；结束确认修复专项 3 个文件、31 个测试通过。
- `pnpm.cmd build` 通过。
- `pnpm.cmd verify:fast` 通过；首次重跑曾因已有开发实例锁住 `relay-pool-desktop.exe` 失败，释放明确的仓库开发进程后复跑通过。
- 独立 identifier 的真实 Tauri WebView 验收通过：全新 profile 自动启动 `basic`，`full` 16 步跨九页连续播放，结束卡片位于遮罩之上，完成 `full` 后九篇页面教程仍为“新增”。
- 教程中心在 1180 x 760 与最小支持窗口 980 x 640 下无横向溢出或按钮越界；路由从“设置”临时切到“概览”后可恢复，渠道从“官方状态”临时切到“本地状态”后可恢复。

长期事实仍以当前代码、自动化契约和 [`../README.md`](../README.md) 为准；本文件保留为一次性实施记录。

## 0. 决策摘要

现有教程基础设施继续使用，不重写 Driver.js 适配、`TourManager` 状态机、跨页导航、目标等待、完成卡片和安装级进度存储。本次只扩展教程的内容模型、页面锚点、有限的可逆视图准备，以及教程中心的信息架构。

本阶段教程体系固定为三类入口中的两类内容：

```text
首次引导（短）
  -> 第一次使用时建立产品认知，可在教程中心重看

页面教程（细）
  -> 分别讲清每个普通工作区的职责、判断方法和操作入口

完整体验（精选）
  -> 按产品信息架构浏览所有普通工作区，但不展开每页全部细节
```

明确不实现“任务教程”。本阶段不要求用户添加中转站、添加密钥、启动代理、发起请求、运行探针或等待异步业务结果；教程只能导航、切换纯视图状态、高亮和解释。

完整体验不是所有页面教程的机械拼接。它独立维护 12--18 个核心步骤，完成状态也独立记录。完成完整体验不能伪造所有页面教程已完成；完成所有页面教程也不能自动把完整体验标记为已完成。

本阶段覆盖九个普通 shell 工作区：

1. 总览
2. 中转站资产
3. 密钥池
4. 路由规则
5. 价格 / 倍率
6. 渠道状态
7. 变更中心
8. 使用记录
9. 设置

采集中心和运行时诊断当前受 `developerModeEnabled` 控制，整页排除。其他页面中仅在开发者模式显示的诊断、决策解释、展开详情和深链入口同样排除。

新增/编辑中转站、新增/编辑密钥、中转站详情、模型基础价格、变更中心设置等 transient 页面暂不进入教程中心。它们依赖选中对象、业务数据或临时导航上下文，无法从一个全局教程入口可靠启动；后续若确有需要，应另做只从当前页面启动的“页面内帮助”，不能伪装成可全局播放的页面教程。

## 1. 当前问题与改造目标

### 1.1 当前问题

当前发布目录只有：

- `full`：机械拼接其他教程；
- `basic`：主要集中在总览和侧边栏；
- `proxy`：设置与路由的三个粗粒度步骤；
- `station-setup`：中转站、密钥池和采集中心的三个粗粒度步骤。

这套目录存在以下问题：

1. 教程按早期“配置场景”切分，无法让用户针对当前页面重看。
2. 多数步骤只说明区域名称，没有解释数据含义、判断方法和下一步入口。
3. `full` 随子教程增长而无限变长，且它与子教程的完成标记互相推导，语义不够清晰。
4. 采集中心步骤带有开发者模式要求，与“普通用户教程不覆盖开发者能力”的新边界冲突。
5. 页面锚点数量不足，不能稳定覆盖价格、渠道状态、变更中心、使用记录和设置的主要区域。
6. 多 Tab 页面只有路由概览具备视图准备，无法可靠介绍路由设置和渠道状态三个视图。

### 1.2 改造目标

- 首次引导控制在 6--8 步，只建立产品结构和核心术语认知。
- 每个普通 shell 工作区都有一篇可独立启动、可重复查看的页面教程。
- 每篇页面教程默认 4--7 步；一步只解释一个概念或判断。
- 完整体验控制在 12--18 步，覆盖全部普通工作区但不复制全部页面步骤。
- 所有教程在无业务数据、查询加载、查询失败和窄窗口下均可安全进入或退出。
- 页面组件只提供稳定锚点和少量可逆视图端口，不读取教程进度、不调用 `TourManager`。
- 教程不调用任何业务 mutation，也不要求用户配合才能进入下一步。
- 旧教程进度可解析、不会触发首次引导重新自动弹出，但不会错误地映射为新页面教程已完成。

### 1.3 成功标准

用户看完任意页面教程后，应能回答三类问题：

1. 这个页面负责什么，不负责什么；
2. 页面上的主要状态或数字应该怎样理解；
3. 需要查看或调整相关能力时，入口在哪里。

教程不以“用户实际完成了配置”为成功标准，也不验证业务结果。

## 2. 内容设计规则

### 2.1 单步文案结构

每个步骤的文案应包含“对象 + 含义 + 使用时机”，避免只复述控件标题。

不推荐：

> 这是密钥池，可以查看密钥。

推荐：

> 只有启用且具备调度资格的密钥才会进入路由候选。请求无法分配时，可以先在这里检查状态、调度资格和监控结论。

文案约束：

- 标题建议 4--10 个汉字；
- 描述建议 35--90 个汉字，最多两句；
- 一步只承载一个主要判断；
- 使用现有领域术语：中转站、中转站 Key、路由候选、本地代理、官方状态、探针；
- 不承诺页面或后端没有提供的能力；
- 不展示真实凭据、完整 URL 查询参数、请求体或其他敏感数据；
- 不使用“点击下一步完成配置”等虚假完成表达。

### 2.2 步骤目标规则

锚点优先级：

1. 页面级稳定区域或固定工具栏；
2. 在 loading / empty / error / ready 状态下都存在的外层容器；
3. 固定 Tab 面板容器；
4. 动态列表或表格外框。

禁止锚定：

- 动态数据中的第一行、某个具体中转站或密钥；
- 中文文本、Tailwind class 或脆弱 DOM 层级；
- 只有开发者模式才渲染的元素；
- 保存、删除、清空、立即执行、启动代理等危险操作按钮；
- 业务 Dialog 内的临时元素；
- 可能因虚拟化、分页或筛选而消失的单条记录。

当教程需要介绍列表字段时，应高亮表头与列表共用的稳定容器；空态也放在同一容器内部。教程可以解释“有数据时这里会显示什么”，不把缺少数据视为错误。

### 2.3 必要步骤与可选步骤

- 只要页面壳层正常渲染，页面教程的核心锚点就必须存在，核心步骤不标记 `optional`。
- 只有受响应式布局、平台能力或非关键可见条件影响的补充说明可以设为 `optional`。
- 不能通过把大量步骤设为 `optional` 掩盖不稳定锚点。
- 目标超时表示锚点契约或页面准备失败；必要步骤进入现有错误/重试界面，不静默跳过。

## 3. 目标教程目录

### 3.1 ID 与分类

建议发布 ID：

```ts
type PublishedTourId =
  | "full"
  | "basic"
  | "dashboard"
  | "stations"
  | "key-pool"
  | "routing"
  | "pricing"
  | "channels"
  | "changes"
  | "logs"
  | "settings";

type TourCategory = "recommended" | "page";
```

`basic` 保留既有 ID，作为首次引导，避免重新定义自动播放主键。`proxy` 和 `station-setup` 从发布目录退出，但作为 legacy ID 保留在进度解析层；旧记录不删除、不展示，也不映射成新页面教程完成。

建议为 `TourDefinition` 增加纯展示元数据：

```ts
type TourDefinition = {
  id: TourId;
  category: "recommended" | "page";
  order: number;
  title: string;
  summary: string;
  revision: number;
  estimatedMinutes?: number;
  steps: readonly TourStep[];
};
```

目录顺序由 `category + order` 决定，不依赖对象键枚举顺序。暂不引入第三个 `task` category，避免代码先于产品范围扩张。

### 3.2 教程中心分组

教程中心固定分为：

```text
推荐
  完整体验 Relay Pool
  快速认识 Relay Pool

页面教程
  总览
  中转站资产
  密钥池
  路由规则
  价格 / 倍率
  渠道状态
  变更中心
  使用记录
  设置
```

每个条目展示标题、摘要、预计时长、状态和开始/重新查看按钮。分组是页面内无卡片嵌套的全宽列表；继续沿用现有紧凑桌面工具样式。状态只来自该教程自己的当前 revision：`新增`、`未完成`、`已完成`、`有更新`。

不再使用 `includesTourIds` 推导完整体验状态。若该字段没有其他用途，应在迁移完成后删除；如为兼容测试暂时保留，也必须停止参与 UI 状态与完成提交。

## 4. 首次引导设计

`basic` 目标是解释软件结构，不展开页面细节。建议 revision 从 `1` 提升到 `2`，共 7 步：

| 顺序 | 页面 | 建议锚点 | 标题 | 内容目标 |
|---:|---|---|---|---|
| 1 | 总览 | `shell-sidebar` | 主要工作区 | 左侧导航对应资产、路由、状态、记录和设置；开发者模式入口不属于本教程。 |
| 2 | 总览 | `dashboard-metrics` | 本地运行概览 | 说明 Relay Pool 对外提供固定本地入口，总览聚合请求、用量、余额和可用密钥。 |
| 3 | 总览 | `nav-stations` | 中转站资产 | 中转站是上游服务入口，负责承载账号、余额、分组等站点事实。 |
| 4 | 总览 | `nav-key-pool` | 中转站 Key | 密钥池管理实际参与访问和调度的 Key；一个中转站可以拥有多个 Key。 |
| 5 | 总览 | `nav-routing` | 路由规则 | 路由从合格 Key 中选择候选，本地入口与上游资产由此连接。 |
| 6 | 总览 | `dashboard-recent-usage` | 使用结果 | 使用记录用于确认请求是否成功、使用了哪个上游以及产生了多少消耗。 |
| 7 | 总览 | `nav-settings` | 设置与教程 | 设置中管理本地代理、网络出口、数据与备份，并可随时重开教程。 |

首次自动播放规则沿用现有契约：旧 revision 已完成或跳过时不自动打断用户；revision 更新只在教程中心显示“有更新”。首次自动播放仍只尝试一次，并在业务 modal 存在时放弃本次启动。

## 5. 页面教程详细设计

以下是内容与锚点契约草案。实现前需逐页确认 DOM 边界，但不得在实现过程中把内容目标缩减为只高亮整个页面。

### 5.1 总览教程 `dashboard`

建议 6 步，不切换页面：

| 顺序 | 建议锚点 | 标题 | 内容目标 |
|---:|---|---|---|
| 1 | `dashboard-metrics` | 本地路由指标 | 区分今日请求、实际消耗、Token、可用密钥、平均耗时和实时流量，说明它们反映本地入口的运行结果。 |
| 2 | `dashboard-station-metrics` | 中转站统计 | 说明站点余额和站点侧请求/消耗来自上游资产事实，口径不等同于本地请求指标。 |
| 3 | `dashboard-risk` | 风险提示 | 解释这里聚合需要处理的问题，严重度和最近出现时间用于决定处理顺序。 |
| 4 | `dashboard-key-health` | 密钥健康 | 说明可用、冷却、禁用等状态影响密钥是否能继续参与路由。 |
| 5 | `dashboard-routing-queue` | 路由候选 | 说明候选 Key 的并发和近期成功率用于观察当前承载情况，而不是手工排队列表。 |
| 6 | `dashboard-recent-usage` | 近期使用 | 说明这里用于快速确认最新请求，完整筛选和详情应进入使用记录。 |

`dashboard-station-metrics` 为新增稳定锚点；其容器必须在无站点数据时仍存在。

### 5.2 中转站资产教程 `stations`

建议 5 步：

| 顺序 | 建议锚点 | 标题 | 内容目标 |
|---:|---|---|---|
| 1 | `stations-toolbar` | 筛选与新增入口 | 说明问题筛选帮助聚焦异常资产，新增按钮只作为入口介绍，教程不会自动打开表单。 |
| 2 | `stations-summary` | 资产概况 | 说明站点数量、健康或问题概况的统计范围。若当前页面没有独立概况，应与工具栏合并而不是制造装饰卡片。 |
| 3 | `stations-list` | 中转站列表 | 说明一行代表一个上游中转站，列表在空态和有数据时共用同一锚点。 |
| 4 | `stations-status-fields` | 状态与风险 | 解释禁用、无可用 Key、采集异常、余额和倍率问题是不同层面的状态，不能互相替代。 |
| 5 | `stations-row-actions` | 详情与维护入口 | 在稳定的列表操作列/表头上说明可进入详情和编辑；不锚定某条真实数据行，不执行删除或充值。 |

若页面无法为“状态字段”和“操作入口”提供不依赖数据行的稳定表头锚点，则合并为一个 `stations-list` 步骤，教程保持 4 步，不创建假数据。

### 5.3 密钥池教程 `key-pool`

建议 5 步：

| 顺序 | 建议锚点 | 标题 | 内容目标 |
|---:|---|---|---|
| 1 | `key-pool-toolbar` | 过滤密钥 | 说明可按中转站和启用状态缩小范围，新增 Key 入口只作说明。 |
| 2 | `key-pool-list` | 密钥池 | 说明每一项是连接上游的独立凭据单元，Key 与中转站是从属关系。 |
| 3 | `key-pool-state-columns` | 状态与调度 | 区分“启用状态”和“是否具备调度资格”，避免把启用误认为一定可路由。 |
| 4 | `key-pool-monitor-column` | 监控结论 | 解释未检测、检测中、正常、降级和错误用于观察连通性与健康，不等于站点官方状态。 |
| 5 | `key-pool-provider-actions` | 归属与维护 | 说明供应商归属、编辑和连通性检查入口；不自动发起真实测试。 |

表头锚点必须覆盖空态时仍渲染的稳定说明区域；若空态不渲染表头，应将字段说明移到 `key-pool-list` 外层并减少步骤。

### 5.4 路由规则教程 `routing`

建议 7 步，包含可逆 Tab 切换：

| 顺序 | 视图 | 建议锚点 | 标题 | 内容目标 |
|---:|---|---|---|---|
| 1 | 任意 | `routing-tabs` | 概览与设置 | 说明概览用于观察当前生效结果，设置用于调整候选范围与评分偏好。 |
| 2 | 概览 | `routing-status-summary` | 当前路由状态 | 解释倍率上限、分组筛选、候选状态和最近路由等摘要。 |
| 3 | 概览 | `routing-candidate-list` | 候选密钥 | 说明只有满足资格的 Key 才会进入候选，排序是多个因素共同作用的结果。 |
| 4 | 概览 | `routing-candidate-factors` | 评分因素 | 解释可靠性、响应速度、成本和偏好是候选比较维度，不展示开发者诊断或内部决策详情。 |
| 5 | 设置 | `routing-policy-scope` | 候选范围 | 说明设置决定哪些分组和 Key 可以参与路由；教程不修改当前配置。 |
| 6 | 设置 | `routing-policy-profile` | 路由偏好 | 说明均衡、稳定、速度、成本等预设如何调整权重，不把预设描述为绝对保证。 |
| 7 | 设置 | `routing-policy-save` | 保存与生效 | 只说明修改后需要显式保存及其生效边界，不点击保存按钮。 |

准备动作新增为受限 key：

  | "none"

  | "routing-settings-tab";

`RoutingViewPreparationPort` 扩展 `showSettingsView()`，两种动作都必须返回幂等 restore callback。退出、跳过、失败、切换教程和组件卸载后恢复用户原 Tab；不能用固定延时猜测 Tab 已切换。

### 5.5 价格 / 倍率教程 `pricing`

## 7. 架构边界与耦合控制

### 7.1 保留的稳定契约

教程与业务页面只允许通过三类契约连接：

```text
AppPageId / TourNavigationPort
data-tour anchor contract
可逆 TourPreparationRegistry key
```

禁止新增以下耦合：

- feature 页面 import `TourManager`、Driver.js、教程目录或进度 store；
- catalog 读取 React Query cache、业务设置或领域对象；
- `TourManager` 调用保存、删除、导入、采集、探针、代理启停等命令；
- catalog 保存 React component、HTMLElement、callback 或 Promise；
- 为教程创建假业务数据；
- 根据列表是否有数据改变教程步骤总数；
- 用 CSS class 或中文文案作为目标选择器。

### 7.2 页面锚点所有权

- 每个锚点由最靠近其语义区域的页面或展示组件拥有。
- anchor 名称使用 `<page>-<concept>`，不使用组件实现名。
- 同一活动 page layer 内 anchor 必须唯一。
- shell 全局锚点继续要求 `data-tour-scope="global"`。
- 页面改版若保留语义区域，应尽量保留 anchor；若语义变化，必须同步 catalog revision 和契约测试。
- 业务组件不接收 `tourActive` 一类 prop，不因教程运行改变业务数据或布局。

### 7.3 纯视图准备

视图准备只允许：

- 切换已有 Tab；
- 展开不会读取敏感数据、不会修改业务状态的固定说明区域；
- 将页面滚动到目标可见区域（优先由 Driver.js / 浏览器原生行为处理）。

每个准备动作必须满足：

1. 幂等；
2. 可取消；
3. 返回只执行一次的恢复函数；
4. session 结束时恢复原视图；
5. 不依赖固定延时；
6. 不调用业务 mutation；
7. 有单元测试覆盖切换、恢复、重复 cleanup 和卸载。

## 8. 进度与版本迁移

### 8.1 建议 revision

实际实施时以合并前目录为基线确认数字，原则如下：

```ts
const TOUR_REVISIONS = {
  full: 2,
  basic: 2,
  dashboard: 1,
  stations: 1,
  "key-pool": 1,
  routing: 1,
  pricing: 1,
  channels: 1,
  changes: 1,
  logs: 1,
  settings: 1,
  // legacy, not published
  proxy: 1,
  "station-setup": 1,
} as const;
```

### 8.2 兼容规则

- `TourId` 可以包含 legacy ID，`PublishedTourId` 只包含当前可启动目录。
- 进度解析器继续接受合法的 `proxy`、`station-setup` 旧记录，避免一次升级造成整个 payload 回退为空。
- 教程中心不展示 legacy 教程。
- legacy 完成记录不映射成 `stations`、`key-pool`、`routing` 或 `settings` 已完成，因为旧教程没有覆盖新内容。
- 已处理过 `basic@1` 的用户不自动播放 `basic@2`，只显示“有更新”。
- `full@2` 只根据 `progress.tours.full` 判断状态，不再聚合其他教程。
- 完成 `full@2` 只提交 `full`；不批量提交页面教程。
- 重置进度保持现有确认流程；若选择全量重置，legacy 记录一并清除。

无需升级 localStorage schemaVersion；现有 V1 的 `Partial<Record<TourId, ...>>` 足以容纳新 ID。只有数据结构本身变化时才新增 schemaVersion。

## 9. 教程中心交互与状态

### 9.1 列表布局

- 推荐区置顶，完整体验为第一项。
- 页面教程按主导航顺序排列。
- 每个条目显示预计时间，例如“约 2 分钟”，但不显示精确秒数。
- 开始按钮在无运行中教程时可用；已有教程运行时沿用 Manager 的有效替换规则。
- 窄窗口下按钮换到下一行，标题、状态和摘要不得与按钮重叠。
- 不在卡片中再嵌套卡片；分组标题和列表使用普通流式布局。

### 9.2 完成语义

- 用户在最后一个实际展示的必要步骤点击完成后，才写入 `completed`。
- 关闭、Esc 或“跳过”写入 `skipped`，状态显示“未完成”。
- 导航失败、目标失败、组件卸载和 Driver 销毁不得写入完成。
- 完成卡片显示刚完成教程的名称，并提供“返回教程中心”或“知道了”；不得用全局泛化文案暗示其他教程也已完成。
- 从完成卡片返回教程中心时，应看到刚完成条目即时更新，其他条目状态不变化。

## 11. 测试计划

### 11.1 Catalog 与进度

- 所有 published ID 唯一且可由 `getTourDefinition` 获取。
- legacy ID 可解析但不可启动、不可出现在教程中心。
- `full` 不再由页面教程步骤拼接。
- 完成 `full` 不改变任何页面教程进度。
- 完成页面教程不改变 `full`。
- `basic@1` 已完成/跳过时不会自动弹出 `basic@2`。
- 新页面教程显示“新增”；旧 revision 显示“有更新”。
- reset 后所有当前及 legacy 记录按既有语义清除。

### 11.2 Manager 与跨页

- 九个页面教程可独立启动。
- 完整体验连续跨九个 route，旧导航和旧 Driver callback 不污染当前步骤。
- 快速连续 next、previous、close 和重新启动保持 session 隔离。
- target timeout 显示可重试错误，不误写完成。
- optional 末步不可见时仍要求显式完成。
- 业务 Dialog 存在时启动被安全拒绝。
- 应用卸载、页面切换失败或 Driver 销毁不伪造完成。

### 11.3 页面准备

- 路由概览/设置来回切换后恢复初始 Tab。
- 渠道三个 Tab 从任意初始 Tab 启动后都恢复原 Tab。
- abort 发生在切换前、切换后和 target 等待期间均能 cleanup。
- cleanup 重复调用无副作用。
- preparation port 未注册时得到明确错误，不退化为固定延时。

### 11.4 DOM 与 UI

- 每个 catalog anchor 在对应活动页面唯一。
- retained 后台页面的同名 anchor 不会被解析。
- loading、empty、error、ready 状态都保留页面教程的核心外层 anchor。
- 开发者模式关闭时可完整播放全部发布教程。
- 开发者模式打开也不会额外插入开发者步骤。
- 业务 Dialog、Driver popover、完成卡片的 z-index 与遮罩层级正确。
- 1280x720、1024x720 和仓库支持的最窄窗口下，popover 不遮住前后按钮且文本不溢出。
- 键盘 Esc、Tab、Shift+Tab 和按钮 focus 恢复符合现有 Driver adapter 契约。

### 11.5 文案审查

- 每一步都说明含义或判断，不只复述区域名称。
- 不包含不存在的功能、内部实现术语或开发者诊断。
- 价格文案符合当前倍率模型。
- 渠道状态明确区分本地状态、官方状态与探针。
- 设置文案不暗示教程会执行备份、迁移或代理启停。
- 所有示例只使用明显假值，不出现 secret。

## 13. 风险与控制措施

| 风险 | 后果 | 控制措施 |
|---|---|---|
| 每页步骤过多 | 用户疲劳，完整体验失控 | 页面教程限制 4--7 步；完整体验独立精选 |
| 锚定动态数据行 | 空态失败、数据变化导致错位 | 只锚定外层、表头、工具栏和固定面板 |
| Tab 准备不可恢复 | 教程退出后改变用户工作现场 | 使用可逆 port、AbortSignal 和幂等 cleanup |
| 教程文案复制业务逻辑 | 业务变化后文案失真 | 只解释稳定领域概念；revision 随语义变化更新 |
| 完成状态互相推导 | 完成标记与实际观看不一致 | 每篇教程独立记录，移除 `includesTourIds` 聚合 |
| 开发者能力泄漏 | 普通用户看到无法访问的功能 | catalog 不声明 developer requirement；普通模式做全量回归 |
| 为教程改造业务 UI | 形成反向耦合和额外维护成本 | 只加语义锚点和窄视图端口，不改业务数据流 |
| transient 页面无法全局启动 | 教程中心入口在无上下文时失败 | 本阶段排除，未来只允许当前页上下文帮助 |
| 页面改版忘记更新教程 | 运行时目标超时 | anchor contract 测试 + catalog revision 评审 |

## 14. 明确非目标

本计划完成后仍然不提供：

- “添加一个中转站并验证成功”教程；
- “配置密钥并完成连通性测试”教程；
- “启动本地代理并发送第一条请求”教程；
- “创建探针并等待检测结果”教程；
- “排查一次失败请求”跨页流程；
- 任何需要用户输入、提交、等待或产生费用的任务教程；
- 采集中心、运行时诊断或开发者详情教程；
- CRUD 表单、详情页和 transient 设置页的全局教程；
- 教程云同步、远程配置、行为统计或 A/B 测试。

这些能力不能在本计划实施过程中顺带加入。若未来重新讨论任务教程，必须单独设计暂停/恢复、用户操作等待、业务结果判定、失败恢复和安全边界，不能复用当前线性页面教程假装完成。

## 15. 完成定义

只有同时满足以下条件，才能把本计划标记为 Completed：

1. `basic`、`full` 和九篇页面教程全部发布；
2. 完整体验不再机械拼接页面教程；
3. 教程中心完成推荐/页面两组布局；
4. 页面教程与完整体验的完成状态完全独立；
5. 所有发布教程在开发者模式关闭时可完成；
6. 无任何发布步骤依赖采集中心、运行时诊断或 developer-only DOM；
7. 无业务 mutation、用户输入或业务结果等待进入教程状态机；
8. 路由与渠道 Tab 准备可逆且通过竞态测试；
9. loading、empty、error、ready 和窄窗口锚点测试通过；
10. 相关 Vitest、`pnpm build` 和实际需要的 `pnpm verify:fast` 通过；
11. 真实 Tauri WebView 验收记录已更新；
12. `docs/README.md` 已指向新的当前实施记录，并清楚保留原基础设施计划的历史作用。
