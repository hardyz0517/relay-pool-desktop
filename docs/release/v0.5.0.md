# Relay Pool Desktop v0.5.0

v0.5.0 是相对 v0.4.6 的技术预览大版本，覆盖 2026-08-19 至 2026-09-07 的 100 次提交。本地 OpenAI-compatible 入口仍然是 `http://127.0.0.1:<port>/v1`，客户端不用改接入方式；变化集中在智能路由、站点采集、价格目录、监控口径、成本完整性和桌面工作区。

数据库从 schema 42 升级到 schema 79。第一次启动可能要更长时间完成迁移，请先备份本地数据目录。

## 相对 v0.4.6，使用上会直接感觉到的变化

- 路由规则从“选中一个结果”变成可解释的工作区：策略、模型映射、候选排序、拒绝原因、能力选择、分数和电路状态可以一起看。
- 路由雷达换成动态地球，用来观察候选和路径，不再是装饰图。
- 官方渠道状态从 v0.4.6 的 Sub2API 只读采集，扩展到 NewAPI 发布性能指标（TTFT / TPS / 成功率）；这些数字仍是中转站发布事实，不和本地主动探测混用。
- 站点采集把过期登录和采集器故障分开。过期授权不会再被说成站点挂了；匹配的采集任务完成后才会恢复授权。
- 充值中心可以发现充值入口，并做兑换控制和协同采集。
- 总览成本会补齐缺失 usage，并显示完整度；请求日志能看到实际上游模型、成本缺口，并用绿 / 黄 / 橙 / 红色条表示延迟。
- 首次启动和常用页面有引导教程；schema 升级进度会显示在启动界面。

## 相对 v0.4.6 改了什么

### 智能路由评分与熔断 v3

- 新增路由策略与模型映射控制面：策略编辑、候选排序、模型映射、拒绝元数据和能力选择进入同一套可解释工作区。
- 引入双窗口 Key 质量评分，界面会解释候选分数，而不只给出最终选中结果。
- 落地重试、故障转移、健康冷却、熔断、告警和传输策略；默认流式空闲超时提高到 180 秒，并等待尾部 usage，减少流式请求过早断开。
- 评分与熔断切换到 v3 控制面：桌面状态、电路诊断、冷却后的逻辑 Half-Open 都消费同一套电路事实。冷却结束的 Key 可直接进入恢复就绪，不再额外过一层分数门槛。
- 退役旧健康执行链，保留已保存的密钥池顺序；监控变化后会重建质量快照。策略增加快速激活通道，设置页可查看激活状态。
- 端点写回改为窄端口保护，避免过期后台任务改写当前健康、凭据或采集事实。
- 路由雷达替换为动态地球可视化，用来观察候选与路径。

### 站点采集、授权与官方状态

- 站点采集改为带围栏的可靠性模型：授权捕获、采集运行、站点详情 revision、collector operations ledger 分开记账。
- 过期授权与采集器失败分开分类；只有匹配的任务完成后才恢复授权。
- 分组描述和 NewAPI 发布性能指标（TTFT / TPS / 成功率）可持久化；站点详情和官方状态表展示这些只读事实。
- 站点启用状态在 API Origin 变更后保持；密钥模型发现会继承站点代理。
- 充值中心可发现充值入口，并增加兑换控制与协同采集。
- 路由候选里的供应商名称可直接打开对应站点详情。

### 余额、监控与价格

- 余额改为按 scope / kind 的权威模型：可用密钥余额优先于空快照，旧聚合余额降为遗留证据，不再靠“把密钥余额加总”去猜账户余额。
- 监控统一可消费性（spendability）与上游失败分类，要求权威证据后才判定可花；探测计时感知代理。
- 价格从旧的 Pricing Rule 收口为模型基准价格目录：目录同步、原生倍率和映射载荷对齐，避免把映射价格写成原生价格。
- 渠道页增加模型能力选择器，监控与站点只读模型分开消费。

### 仪表盘、成本与请求日志

- 仪表盘成本读取会重建过期 rollup，并套用尾窗；缺失 usage 的成本会落库并叠加到汇总，同时显示完整度。
- 请求日志压缩可观测列，记录实际解析到的上游模型，并按成本缺口分类、筛选 usage 记录。
- 延迟色条使用独立的绿 / 黄 / 橙 / 红档位，分别对应正常、注意、警告和严重，不再复用平台语义色。
- 总览最近用量、路由队列、分页控件和翻转菜单按高密度桌面工具收紧；密钥池监控刷新不再把列表顶走。
- “degraded” 文案改为「欠佳」，避免把可恢复状态说成全面故障。

### 变更中心、告警与启动恢复

- 变更中心分页、未读计数和分组倍率保留逻辑收口；重复事件通知会被抑制，活动列表按首次出现时间排序。
- schema 15 及后续升级改为可续跑；启动界面展示 schema 升级状态。旧 gen1 升级路径退役。
- 引导教程覆盖首次短引导、精选完整流程和普通页面教程；Driver.js 只负责渲染，状态与跨页导航由应用端口层管理。

### 数据与契约

新增 schema 43 到 79，按主题大致是：

- 43–47：模型映射、文档同步、原生能力、拒绝元数据、遗留优先级
- 48–59：路由保护、错误率、策略/超时物化、监控可消费性、代理探测、采集超时
- 60–71：路由 v3 策略、观察、电路、generation、资格报告和生命周期修复
- 72–74：站点采集可靠性、operations ledger、详情 revision
- 75–79：请求日志上游模型、余额 kind/scope、分组描述、NewAPI TTFT/TPS/成功率

前后端 IPC、TypeScript 绑定、架构检查和冻结迁移夹具同步更新；schema 升级模块可在 CI 中按块续跑。

## 升级前

- 升级或安装前，请先从系统托盘完全退出 Relay Pool Desktop。
- 升级前请备份本地数据目录。本次跨多个 schema，中断或混用旧版本风险更高。
- 请勿让多个 Relay Pool Desktop 版本同时操作同一个本地数据目录。
- 升级后第一次启动若正在迁移，请等待完成，不要强制结束进程。

## 已知边界

- 本版本仍主要面向 Windows x64 认证。
- 应用是本地桌面工具，不是托管中转服务或团队管理系统。
- 官方渠道状态仍以中转站发布信息的只读采集为准，不直接替代本地主动探测或路由健康判断。
- 路由 v3 旧链代码已退役，但不可逆的历史 schema 删除仍未做；不要用本版本当数据清理工具。
- API key、cookie、本地数据库、日志和本地配置文件必须保持在受跟踪项目文件之外。
